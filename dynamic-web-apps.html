6. Dynamic Web Apps

A static website displays the same content to everyone. The pages are fixed files served to anyone who requests them. There is no memory between visits and no personalization.

A dynamic web application stores, retrieves, and responds to data. A to-do list app remembers your tasks. A social media feed shows you different posts than it shows someone else. An online store knows what's in your cart.

  • The key difference is whether users can modify data. A dynamic web application allows users to create, read, update, and delete data (often abbreviated as CRUD). You can add a new post, edit your profile, remove an item from your cart. The application responds to your actions by changing what's stored. That's what makes it "dynamic."

6.1 Architecture of a Dynamic Web App: Backend and Frontend

Dynamic web applications are divided into a backend and the frontend.

A backend consists of a database for storing persistent information like user accounts, passwords, posts, or anything that needs to survive beyond a single session. Users can create, replace, update, and delete data (CRUD) in the database depending on their permissions.

  • Users never see the backend and don't access the database directly. Instead, they interact with the frontend, which communicates with the database behind the scenes.

A frontend consists of everything that runs in the user's browser: buttons, forms, text, images, animations. When someone visits your web app, the frontend code is downloaded to their browser and executes on their device.

  • The frontend communicates with the backend through an API (Application Programming Interface)—a structured protocol for sending requests and receiving responses. This requires the dynamic web application be hosted on a server that supports APIs.

6.1.1 Example: A Complete Interaction

Consider what happens when you order food through a delivery app:

  1. User opens the app: The browser downloads the frontend and renders the interface—the restaurant listings, menu items, and buttons.
  2. User logs in: The frontend sends credentials to the backend via the API. The backend checks the database to verify the email and password match, then returns the user's identity. The frontend now knows who is logged in.
  3. App loads user data: The frontend requests data from the backend: saved addresses, payment methods, order history. The backend retrieves this from the database and returns it. The frontend applies business logic (e.g., show the default address first) and displays the result.
  4. User browses restaurants and adds items to cart: The frontend may store cart contents locally, or send each addition to the backend. Either way, the frontend updates the display to show the current cart.
  5. User clicks "Submit Order": The frontend sends the order details to the backend via the API. The backend saves the order to the database, processes payment, notifies the restaurant, and sends a confirmation back through the API. The frontend displays "Order Confirmed!"
  6. User closes the app: The session may persist (staying logged in) or end. The order remains in the database—when the user reopens the app, they can see their order history.

6.2 What We Need to (Ask Cursor to) Build

Creating a dynamic web application with Cursor is not much more complicated than creating a static website. We just have to know what to ask for.

For the backend we need a database to store and handle data. Building a secure database system from scratch takes weeks or months—these systems involve security vulnerabilities, scaling, data consistency, and crash recovery.

  • Our solution: We'll use InstantDB, a free service that provides a database, authentication, and data synchronization out of the box. Rather than setting up and maintaining your own database, InstantDB handles all of this as a managed service, letting you focus on your app's unique features.

    Tip: After we create the database at InstantDB.com, we will ask Cursor to read their documentation and program the connection so we don't have to do it ourselves.

For the frontend we'll ask Cursor to build our website with a framework—a pre-built set of tools that enable communication with the backend through an API.

  • Our solution: We'll ask Cursor to build our application with Next.js, a frontend framework built on React (a popular software for building user interfaces).

    Tip: Cursor is already very familiar with Next.js and should have no problem building this from a simple prompt.

Finally, our dynamic app needs a different hosting solution to be accessed on the internet. Previously, we hosted our static sites on GitHub Pages—but GitHub Pages cannot host the backend that a dynamic app requires.

  • Our solution: We'll host our web application on Vercel. Since Vercel developed Next.js in 2016, their free hosting service is a natural fit.

    Tip: The good news is that all we have to do is create a free account at Vercel.com, link it to our GitHub repository, and let it handle the rest.

6.2.2 Exercise 2: Setup the Backend: Create a New App on InstantDB ✅

InstantDB provides a database and authentication for your app—no need to build these from scratch.

  1. Go to instantdb.com and create an account (sign up with your email)
  2. After signing in, go to the dashboard at instantdb.com/dash
  3. Click "Create App"
  4. Name your app (e.g., poetry-app) and click Create
  5. You'll see your App ID—a long string of letters, numbers, and dashes that looks like this: 
    566ffee5-e773-4b68-a132-29678f8f6eea
  6. Copy your App ID right now and save it somewhere safe—a notes app, a text file, or even a sticky note. You'll need it in Exercise 4.

What you learned: InstantDB gives you a backend database without building one from scratch. The App ID is how your app will connect to your specific database.

What is the App ID?

Think of the App ID like a mailing address for your database. When your app wants to read or write data, it needs to know where to send the request. The App ID tells InstantDB "this request is for THIS specific app's data, not someone else's."

The App ID is public—it's safe to include in your code. It's not like a password. InstantDB uses a separate permissions system to control who can actually read or write data. Think of it like your home address: it's public information, but that doesn't mean anyone can walk into your house.

6.2.3 Exercise 3: Add InstantDB's Documentation to Cursor ✅

Cursor's AI might not know newer tools like InstantDB well. By adding InstantDB's documentation, you give Cursor a reference to generate accurate code.

  1. Open Cursor Settings: press Cmd+, (Mac) or Ctrl+, (Windows)
  2. In the settings search bar, type Docs
  3. Click on Features in the sidebar, then find the Docs section
  4. Click "Add new doc"
  5. Enter this URL:
https://www.instantdb.com/docs
  1. Press Enter and wait for Cursor to finish indexing (this may take a minute)
  2. You should see "InstantDB" appear in your docs list

What you learned: You can add documentation for any tool to Cursor. This is especially useful for newer or less common tools that Cursor's AI might not know well.

When do you need to add documentation?

  • For newer or less common tools (like InstantDB)
  • When you're getting incorrect or outdated code suggestions
  • When working with a tool's newest features

When is it not necessary?

  • For very popular, well-established tools (like React or basic JavaScript)
  • For simple, standard patterns the AI has seen millions of times

Now let's put everything together. You'll create a simple poetry sharing website where users can create an account, log in, and share their own poems. Posted poems are visible to all users on the home page.

Step 2: Prompt Cursor to Plan and Build

  3. In the Composer input, type @ and select InstantDB from the docs list. This tells Cursor to reference the documentation you added in Exercise 3.

    Tip: You won't see @InstantDB appear as text—it shows up as a tag in the input. That's expected.

  4. Copy the prompt below and paste it into the Composer. Before sending, replace YOUR_APP_ID_HERE with the App ID you copied in Exercise 2.
Refer to the @InstantDB documentation. 
Build a simple poetry sharing website using Next.js and Tailwind CSS.
Use InstantDB for the database and authentication.

My InstantDB App ID: YOUR_APP_ID_HERE

Requirements:
- Users can sign up and log in with magic code authentication
- Logged-in users can post a poem (title and body)

The app will be deployed to Vercel. Use Vercel’s Next.js deployment and build documentation @Vercel so the project is ready to deploy
  1. Review the plan Cursor generates. You can edit it directly—add, remove, or change steps if you like

    Tip: Cursor may ask to run terminal commands (like npx create-next-app) during the build. Click Accept when prompted—these commands set up the project structure and install the required packages.

What you learned: You can describe a dynamic web application in plain language and let Cursor plan and build it. By referencing InstantDB's documentation with @InstantDB, you helped Cursor use the correct APIs. The App ID connects your app to the database you created in Exercise 2.

Alternatives: InstantDB and Vercel are not the only solutions. Supabase is a popular alternative backend that provides a PostgreSQL database, authentication, and real-time features. Netlify is a common alternative to Vercel for hosting dynamic web applications. Both work well with Next.js, but they require more technical setup than the tools we've chosen for this bootcamp.

6.2.5 Push Your Project to GitHub

You pushed projects to GitHub in Our Tools (Exercise 10) and our first meeting. Do the same here for your dynamic-app-tutorial project. Ask Cursor to do the push for you—don't use the terminal or Source Control pane yourself.

6.2.5 Exercise 5: Create a GitHub Repository and Push Your Project ✅

  1. Create a new repository on GitHub:
    • Go to github.com/new
    • Name it dynamic-app-tutorial (or whatever you'd like to call it)
    • Leave it set to Public
    • Don't initialize with a README, .gitignore, or license—your project already has files
    • Click Create repository
  2. Copy the repository URL from the page GitHub shows you (e.g. https://github.com/your-username/dynamic-app-tutorial)
  3. Open Cursor's Agent (Cmd+I or Ctrl+I) and ask it to push your project: 
    Push this project to my GitHub repository at https://github.com/your-username/dynamic-app-tutorial

    Tip: Replace the URL in the prompt with your actual repository URL. Cursor will initialize Git if needed, stage your files, commit, and push—you don't need to run any commands yourself.

  4. Verify the push worked: go to your repository on GitHub (the URL you copied in Step 2) and confirm your project files are there.

What you learned: You can push any project to GitHub by creating a repository and asking Cursor to handle the push. This is your third time doing it—it should feel familiar by now.

Asking Cursor to do the work for you: Pushing to GitHub requires Cursor to submit commands to the terminal. As a safety feature, Cursor might ask for your permission to run certain commands, or insist you enter them yourself.

If this happens, either grant the permission in real-time, or copy the commands Cursor provides—they'll typically look something like git add ., git commit -m "your message", and git push origin main—and paste them into your terminal one at a time. You can open the terminal in Cursor by pressing Ctrl+` (that's the backtick key, usually above the Tab key).

6.2.6 Deploy to Vercel

GitHub Pages can host static websites, but your dynamic web application needs a hosting platform that supports backends and APIs. Vercel connects to your GitHub repository and automatically builds and deploys your app every time you push code.

6.2.6 Exercise 6: Create a Vercel Project and Link It to GitHub ✅

  1. If you don't already have a Vercel account, create one:
    • Go to vercel.com and click Sign Up
    • Choose Continue with GitHub and authorize Vercel to access your GitHub account
    • When prompted, select the Hobby plan (free)
  2. From the Vercel dashboard, click Add New... → Project
  3. Under Import Git Repository, find and select the repository you created in Exercise 5, then click Import

    Tip: If you don't see your repository listed, click Adjust GitHub App Permissions to grant Vercel access to additional repositories.

  4. On the Configure Project page, Vercel will auto-detect your project as a Next.js app. Review the settings—the defaults should work. If your app uses environment variables (e.g. for your InstantDB App ID), expand the Environment Variables section and add them before deploying.

    Tip: If your InstantDB App ID is hardcoded in your source files (as in Exercise 4's prompt), you don't need to add environment variables. If Cursor stored it in a .env.local file instead, add the variable name and value here so Vercel can access it.

  5. Click Deploy and wait for the build to finish (typically 1–3 minutes). Vercel will show a progress log as it builds your app.
  6. When the build succeeds, Vercel will show a congratulations page with a preview of your app. Click the preview image or the generated URL (e.g. dynamic-app-tutorial.vercel.app) to visit your live app.

    Tip: If the build fails, click View Build Logs to see what went wrong. Common issues include missing dependencies or build errors in your code. Copy the error message and paste it into Cursor's Agent to get help fixing it.

Your dynamic web app is now live on the internet. Try visiting the URL on your phone—it works on any device. Every time you push new code to GitHub, Vercel will automatically rebuild and redeploy your app.

What you learned: Vercel connects to your GitHub repository and handles deployment automatically. Unlike GitHub Pages, Vercel can host dynamic web applications with backends and APIs—exactly what your Next.js + InstantDB app needs.
