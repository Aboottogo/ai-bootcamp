7. Build Your Own Web App

Goal: Leave this session with a working version of your app—with user accounts and a real database—live on the internet.

In our first meeting, you built a how-to tutorial for your app and deployed it to GitHub Pages. For homework, you followed that tutorial to start building the app itself. Today you'll make it real: you'll add a database and user accounts with InstantDB, then deploy the finished app to Vercel. By the end of today, you'll have a URL like your-project.vercel.app that anyone can visit from any device.

  1. Set up your backend (InstantDB)
  2. Ask Cursor to build your dynamic app
  3. Test your app locally
  4. Push to GitHub and deploy to Vercel

7.1 Set Up Your Backend

In the first half of today's session, you built a sample poetry app using InstantDB and deployed it to Vercel. Now you'll do the same thing for your own project. You need a separate InstantDB app for your project—the one from the exercises was for the poetry demo.

7.1.1 Create an InstantDB App for Your Project

This is the same process you followed in Dynamic Web Apps (Exercise 2), but for your own project.

  1. Go to the InstantDB dashboard at instantdb.com/dash
  2. Click "Create App"
  3. Name it after your project (e.g. studysync, potluckpal, chorechart)
  4. Copy your App ID and save it somewhere safe—you'll need it in the next step.

    Tip: If you already created an InstantDB app for your project while following your tutorial as homework, you can reuse that App ID. You don't need to create a new one.

Before you continue, make sure you have these three things ready:

  • Node.js installed — If you followed along with Exercise 1 earlier today, you're set. If not, ask Cursor: Can you check if Node.js is installed?
  • InstantDB docs added to Cursor — You did this in Exercise 3. If you skipped it, open Cursor Settings, go to Features → Docs, click "Add new doc," and enter https://www.instantdb.com/docs
  • Your my-app-idea.md file — The same file you created in Project Ideas and used in our first meeting. Have it somewhere you can attach it in Cursor.

7.2 Ask Cursor to Build Your App

In Dynamic Web Apps (Exercise 4), you used Plan mode to build a poetry sharing app with Next.js and InstantDB. Now you'll use the same approach—Plan mode, review, Build—but for your own app idea. The prompt below tells Cursor everything it needs to build a working app from your my-app-idea.md.

7.2.1 Build Your Dynamic App

  1. Create a new folder on your computer for your app (e.g. my-app in Documents—avoid spaces in the name) and open it in Cursor (File → Open Folder).

    Tip: Use a fresh folder even if you started building during homework. Starting clean with a single prompt gives Cursor the best chance of producing a working app. You can always reference your homework project for ideas.

  2. Have my-app-idea.md ready—either in the project folder or somewhere you can attach it.
  3. Open the Agent (Composer) with Cmd+I (Mac) or Ctrl+I (Windows), then press Shift+Tab to switch to Plan mode.
  4. In the Composer input, type @ and select InstantDB from the docs list. This tells Cursor to reference the documentation you added in Exercise 3.

    Tip: You won't see @InstantDB appear as text—it shows up as a tag in the input. That's expected.

  5. Copy the entire prompt below, paste it into the Composer input, and attach your app-idea file (click the + button or type @ to add my-app-idea.md). Before sending, replace YOUR_APP_ID_HERE with the App ID you copied in the previous step. 
    I am a business student building my first web app with AI assistance. I have **never written code before**. I have attached my app idea file (`my-app-idea.md`) which describes the app I want to build. Please read it carefully before proceeding.

## Your Task
Build a **dynamic web application** based on my app idea.

## Tech Stack
- **Next.js** with App Router
- **InstantDB** for the database and authentication (Magic Code login)
- **Tailwind CSS** for styling

My InstantDB App ID: YOUR_APP_ID_HERE

## Requirements
- Users can sign up and log in with **magic code authentication** (email + 6-digit verification code)
- Implement the **core features** described in my app idea file
- Each user's data is **associated with their account**
- The design should be **clean, modern, and mobile-responsive**
- Use **InstantDB's `db.useQuery()`** for reading data and **`db.transact()`** for writing data
- Use **InstantDB's `db.useAuth()`** for authentication state

## Structure
Follow this project structure:
```
src/
  app/
    layout.tsx      # Root layout with providers
    page.tsx        # Home page
    login/
      page.tsx      # Login page
    [other routes as needed]
  components/
    [reusable components]
  lib/
    db.ts           # InstantDB initialization
instant.schema.ts   # InstantDB schema definition
```

## Important
- Please read the **InstantDB documentation** I've attached (@InstantDB) to ensure you use the correct APIs for database queries, transactions, and authentication.
- The app must be **deployable to Vercel** with no additional configuration beyond setting the `NEXT_PUBLIC_INSTANT_APP_ID` environment variable.
- Read **Vercel's Next.js deployment and build documentation** @Vercel to ensure the project is ready to deploy.
- Keep the data model simple: **2–4 entities maximum**.
- Make the app **encouraging and easy to use** for first-time visitors.

    Tip: Copy the prompt exactly as given, but make sure to replace YOUR_APP_ID_HERE with your actual App ID before sending.

  6. Review the plan Cursor generates. You can edit it directly—add, remove, or change steps.

    Tip: Cursor may ask clarifying questions about your app. Answer based on your my-app-idea.md. If you're unsure, keep it simple—you can always add features later.

  7. When the plan looks good, click Build and let Cursor create the files.

    Tip: Cursor may ask to run terminal commands (like npx create-next-app or npm install) during the build. Click Accept when prompted—these commands set up the project structure and install required packages.

Already have a working project from homework? If you followed your tutorial and already have a Next.js + InstantDB app that's working, you don't need to start from scratch. Instead, open your existing project in Cursor and use this shorter prompt to verify and improve it:

Review this project and make sure InstantDB authentication and database operations are working correctly. Check that users can sign up, log in, and that data is saved to InstantDB. Fix any issues you find.

Then skip ahead to 7.3 Test Your App Locally.

7.3 Test Your App Locally

Before deploying, make sure your app works on your computer. This is your chance to catch and fix issues while you're still in the meeting with help available.

7.3.1 Run and Test Your App

  1. Start the development server. Open Cursor's Agent (Cmd+I or Ctrl+I) and ask: 
    Start the development server for this project.

    Tip: You can also run npm run dev directly in the terminal (Ctrl+`). Either way, you should see a message like "Ready on http://localhost:3000".

  2. Open http://localhost:3000 in your browser.
  3. Test sign-up: Enter your email address. Check your email for a 6-digit verification code and enter it. You should be logged in.
  4. Test your core features: Create some data (e.g. add an item, post a message, create an event—whatever your app does). Make sure you can view, edit, and delete it.
  5. Test persistence: Log out, then log back in. Your data should still be there.
  6. Check the InstantDB dashboard: Go to instantdb.com/dash, select your app, and click on the Explorer tab. You should see the data you just created.

    Tip: If you don't see any data in the dashboard, your app may not be connected to InstantDB correctly. Double-check that your App ID is correct in the code.

You're done when: You can sign up, log in, create and view data, and see that data in the InstantDB dashboard.

Something not working? Don't worry—this is the most common place to hit issues. Try these steps:

  • Build errors or "Module not found": Run npm install in the terminal, then try npm run dev again.
  • Page is blank or shows an error: Open the browser's developer console (Cmd+Option+J on Mac, Ctrl+Shift+J on Windows), copy the error, and paste it into Cursor's chat. Ask Cursor to fix it.
  • Authentication not working: Verify your App ID is correct. Check that it matches the one in your InstantDB dashboard.
  • Data not saving: Ask Cursor: Data isn't being saved to InstantDB. Can you check the database queries and transactions?

If you're stuck, paste the error message into Cursor and describe what you expected to happen. Cursor can see your code and the error, which is usually enough to diagnose the issue.

7.4 Push to GitHub

You've pushed projects to GitHub multiple times now—in Our Tools, our first meeting, and Dynamic Web Apps. Same process here.

7.4.1 Create a GitHub Repository and Push Your Project

  1. Create a new repository on GitHub:
    • Go to github.com/new
    • Name it after your app (e.g. studysync, potluckpal, chorechart)
    • Leave it set to Public
    • Don't initialize with a README, .gitignore, or license—your project already has files
    • Click Create repository
  2. Copy the repository URL from the page GitHub shows you (e.g. https://github.com/your-username/my-app)
  3. Open Cursor's Agent (Cmd+I or Ctrl+I) and ask it to push your project: 
    Push this project to my GitHub repository at https://github.com/your-username/my-app

    Tip: Replace the URL with your actual repository URL. Cursor will initialize Git if needed, stage your files, commit, and push.

  4. Verify the push: go to your repository on GitHub and confirm your project files are there.

Asking Cursor to do the work for you: Pushing to GitHub requires Cursor to submit commands to the terminal. As a safety feature, Cursor might ask for your permission to run certain commands, or insist you enter them yourself.

If this happens, either grant the permission in real-time, or copy the commands Cursor provides—they'll typically look something like git add ., git commit -m "your message", and git push origin main—and paste them into your terminal one at a time. You can open the terminal in Cursor by pressing Ctrl+` (that's the backtick key, usually above the Tab key).

7.5 Deploy to Vercel

You deployed the poetry app to Vercel in Dynamic Web Apps (Exercise 6). Same process here—connect your GitHub repository to Vercel and let it handle the rest.

7.5.1 Deploy Your App to Vercel

  1. Go to your Vercel dashboard at vercel.com and click Add New... → Project
  2. Under Import Git Repository, find and select the repository you just pushed, then click Import

    Tip: If you don't see your repository listed, click Adjust GitHub App Permissions to grant Vercel access to the new repository.

  3. On the Configure Project page, Vercel will auto-detect your project as a Next.js app. If your InstantDB App ID is stored in a .env.local file rather than hardcoded, expand the Environment Variables section and add:
    • Name: NEXT_PUBLIC_INSTANT_APP_ID
    • Value: your App ID from Step 7.1.1

    Tip: If your App ID is hardcoded directly in the source files, you can skip the environment variable. If you're unsure, add it anyway—it won't cause problems.

  4. Click Deploy and wait for the build to finish (typically 1–3 minutes).

    Tip: If the build fails, click View Build Logs to see what went wrong. Copy the error message and paste it into Cursor's Agent to get help fixing it. After fixing, push the changes to GitHub and Vercel will automatically rebuild.

  5. When the build succeeds, Vercel will show a congratulations page with a preview. Click the preview image or the generated URL (e.g. my-app.vercel.app) to visit your live app.
  6. Test your live app: Sign up, log in, and create some data on the live URL—just like you did locally. Make sure everything works.

Your app is now live on the internet. Send the link to a friend. Open it on your phone. This is the URL you'll share in your Share And Present presentation.

Automatic redeployment: From now on, every time you push new code to GitHub, Vercel will automatically rebuild and redeploy your app. You can keep improving your app in Cursor, push the changes, and see them go live within a couple of minutes—no manual deployment needed.
