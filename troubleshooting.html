9. Troubleshooting

This page is a reference for solving problems you encounter while building your project. When something breaks—a blank screen, an error message, unexpected behavior—come here for a structured approach to diagnosing and fixing it.

In this bootcamp, you are the director, not the coder. Your job is to clearly describe what is wrong and what you want to happen. Cursor's job is to find and fix the problem in the code. You should never need to read, interpret, or edit code yourself. If you find yourself staring at code trying to understand it, stop—describe the problem to Cursor instead.

9.1 A Systematic Approach to Problem Solving

When something goes wrong, resist the urge to immediately type "fix it" into Cursor. Follow these five steps every time.

9.1.1 Step 1: Identify the Problem

Before you ask Cursor to fix anything, get clear on what the problem actually is. Ask yourself two questions:

  • What did I expect to happen? (e.g., "I expected the homepage to show a list of recipes.")
  • What actually happened? (e.g., "The page is blank," or "I see a red error message," or "The wrong data is showing up.")

The gap between those two answers is the problem. Being specific about this gap is the single most important thing you can do to help the AI fix it quickly.

9.1.2 Step 2: Capture the Evidence

Gather the information Cursor will need to diagnose the issue:

  • Error messages: If you see an error message anywhere—in the browser, in the terminal (the dark panel at the bottom of Cursor where commands run), or in a popup—select the entire error message text and copy it (Cmd+C on Mac, Ctrl+C on Windows). You do not need to read or understand the error yourself. The AI will interpret it for you.
  • Screenshots: If the problem is visual (something looks wrong, a button is in the wrong place, the layout is broken), take a screenshot. You can attach screenshots directly to your Cursor prompt (see Section 9.2.2).
  • What you just did: Think about the last thing you asked Cursor to do before the problem appeared. This context is often the key to finding the fix.

9.1.3 Step 3: Describe the Problem in a New Agent Session

An agent session is a single conversation with Cursor's AI. Open a new one by pressing Cmd+Shift+I (Mac) or Ctrl+Shift+I (Windows), or by clicking the + button at the top of the agent panel. Starting fresh gives the AI a clean slate with no leftover confusion from previous conversations.

Describe the problem clearly. A good problem description includes three things:

  1. What you were trying to do
  2. What happened instead
  3. The evidence (pasted error message or attached screenshot)

Example of a strong prompt:

I asked Cursor to add a login page to my app. The login page now appears, but when I click the "Submit" button, nothing happens. Here is the error message from the terminal:

[paste error message here]

Example of a weak prompt:

It's broken, please fix it.

The more specific you are, the faster the AI can solve the problem.

9.1.4 Step 4: Evaluate the Result

After Cursor proposes a fix, check whether it actually solved the problem:

  • Does the app now behave the way you originally expected?
  • Did the fix create any new problems?

If the fix worked, move on. If it didn't, proceed to Step 5.

9.1.5 Step 5: If Worse, Undo and Try Again

If Cursor's fix did not work, or if it introduced new problems, do not keep asking the same session to fix it. This often leads to a cycle where each "fix" breaks something else (see Prompt Spirals). Instead:

  1. Undo the changes (see Section 9.4.1)
  2. Open a new agent session
  3. Rephrase the problem differently, or try a different model (see Section 9.3.2)

The Golden Rule: Ask One Thing at a Time. When you have multiple problems, it is tempting to list them all in one prompt. Don't. The AI performs significantly better when it can focus on a single, well-defined problem.

  • Good: "The navigation bar is not showing up on the homepage."
  • Bad: "The navigation bar is not showing up, the fonts are wrong, the footer overlaps the content, and the login page has a bug."

Fix one thing. Confirm it works. Then move to the next.

9.2 How to Show Cursor What's Wrong

Cursor can only help you if it understands the problem. This section covers the specific ways to give it the information it needs.

9.2.1 Error Messages

An error message is text—usually red or yellow—that appears when something goes wrong. You'll see them in the browser, in the terminal panel at the bottom of Cursor, or in popups. They look like nonsense, but they contain precise information the AI can use to locate and fix the problem.

Steps:

  1. Select the entire error message text. Do not try to pick out the "important" part; copy all of it.
  2. Copy it (Cmd+C on Mac / Ctrl+C on Windows).
  3. Paste it directly into your Cursor agent prompt (Cmd+V / Ctrl+V).
  4. Add a sentence or two above it describing what you were doing when the error appeared.

9.2.2 Screenshots

If the problem is something you can see—a visual bug, a broken layout, an element in the wrong place—a screenshot is often worth more than a written description.

To take a screenshot:

  • Mac: Press Cmd+Shift+4, then drag to select the area.
  • Windows: Press Win+Shift+S to open the snipping tool, then select the area.

To attach a screenshot to a Cursor prompt: Click the attachment icon (paperclip or image icon) near the text input area and select your screenshot file, or paste the screenshot directly into the chat input (Cmd+V / Ctrl+V). Add a written description alongside it, such as: "The button should be centered, but it is stuck in the top-left corner. See the attached screenshot."

9.2.3 The Built-In Browser

Cursor has a built-in browser that allows the AI to see your running application the same way you do. This is especially useful for visual or interactive bugs because it lets the AI observe the problem directly, without you needing to describe it perfectly in words.

How to use it:

  1. Make sure your app is running (the preview or localhost URL is active in the browser).
  2. In your agent prompt, ask Cursor to open and inspect your app. For example:
Open my app in the browser and check why the homepage is showing a blank white screen.

The AI will launch the browser, navigate to your app, and observe the result—including visual layout, console errors, and behavior.

9.2.4 @ References

The @ symbol in Cursor points the AI to a specific file, folder, or piece of context in your project. This helps the AI focus on the right area instead of searching your entire project.

How to use it:

  1. In the agent chat input, type @.
  2. A dropdown menu will appear showing files and folders in your project.
  3. Select the file that is relevant to your problem.

When to use it: If you know which file or area of your project the problem relates to—usually the file Cursor most recently edited—reference it with @ so the AI starts there. For example:

The homepage is showing an error after the last edit. Please check @index.html and fix the issue. Here is the error message: [paste error]

You do not need to know what the file contains—you just need to know which file is relevant.

9.3 Cursor Modes and Models

Cursor has several tools specifically useful when debugging. This section explains what they are, when to use them, and how. For a general overview of all modes, see the callout box in Our Tools (Section 4.1).

9.3.1 Debug Mode

Debug mode is a specialized mode in Cursor designed specifically for finding and fixing errors. When you activate it, the AI takes a more systematic, investigative approach: it reads error logs, traces the problem through your project files, tests potential fixes, and iterates until the issue is resolved—all without you needing to understand what it is doing.

Think of it this way: the normal Agent mode is like asking someone to make an edit. Debug mode is like calling in a specialist to diagnose a problem.

When to use it:

  • You have an error message and the normal Agent was not able to fix it.
  • Something that was working before has stopped working.
  • The app crashes, shows a blank screen, or behaves unexpectedly.
  • You've tried a fix in a regular agent session and it made things worse.

How to activate it:

  1. Open the Cursor agent panel (the chat interface on the side of the screen).
  2. Switch the agent mode to Debug using the mode selector near the top of the panel.
  3. Paste in the error message or describe the problem.
  4. Press Enter. The debug agent will begin working.

Tip: Let it run. The debug agent often needs several steps to resolve an issue. Do not interrupt it mid-process unless it seems stuck in a loop (repeating the same action over and over). If it cannot solve the problem after a full run, open a new session and try rephrasing or switching models.

9.3.2 Choosing a Model

When you use Cursor, the AI behind it is powered by a large language model (LLM)—a program trained on large amounts of text and code to understand and generate language. Cursor gives you access to several different models, each with different strengths. Think of them like different specialists: one might be fast and good at routine tasks, another might be slower but more thorough with difficult problems.

How to switch models:

  1. In the agent chat panel, find the model selector—a dropdown menu near the input area that shows the currently selected model name (e.g., "Claude Sonnet 4").
  2. Click the dropdown and select a different model.
  3. Start a new agent session after switching. Do not continue an existing conversation with a different model.

A practical rule of thumb: Start with Sonnet for most tasks. If it cannot solve the problem after one or two attempts, switch to Opus (a more thorough model). If neither is working, try running models in parallel (see below).

9.3.3 Running Models in Parallel

Instead of trying one model, waiting for the result, and then trying another, Cursor allows you to send the same prompt to multiple models at the same time. Each model works on the problem independently, and you can compare the results side by side—like getting a second and third opinion simultaneously.

How to do it:

  1. Open the agent panel and compose your prompt (with the error message or screenshot attached).
  2. In the model selector dropdown, look for the option to enable multiple models or add models.
  3. Select two or three models (e.g., Sonnet and Opus, or Sonnet and Gemini).
  4. Submit the prompt. Each model will generate its own response.
  5. Review the results from each model. Test each solution by running the app and checking whether the problem is fixed.

If multiple solutions work, go with whichever one did not introduce new issues. If none of them work, rephrase the problem and try again in a new session.

9.4 Recovery: Undo, Revert, and Start Over

Not every fix will work on the first try. This section covers how to recover when things get worse instead of better.

9.4.1 Undoing Changes

When Cursor proposes changes to your project, you will see a diff view—a display showing what was added, removed, or modified. You can:

  • Accept the changes (apply them to your project).
  • Reject the changes (discard them so your project stays as it was).

If you already accepted changes and then realize they broke something, use Undo (Cmd+Z on Mac / Ctrl+Z on Windows) to step backward. Cursor keeps a history of changes, so you can undo multiple steps.

9.4.2 Starting a New Agent Session

This is one of the most underused strategies. If the AI has been going back and forth trying to fix something and it is not converging on a solution, the conversation history itself may be confusing the model. Starting a fresh session gives the AI a clean slate.

When to start a new session:

  • The AI keeps repeating the same fix that did not work.
  • Each "fix" is introducing new problems.
  • You have gone back and forth more than two or three times without progress.

To open a new session: press Cmd+Shift+I (Mac) / Ctrl+Shift+I (Windows), or click the + button at the top of the agent panel.

9.4.3 Prompt Spirals

A prompt spiral is when you tell the AI something is broken, it tries to fix it, the fix breaks something else, you report the new problem, it tries to fix that, and the cycle continues—with the project getting worse at each step. Prompt spirals happen because the AI is building on a growing history of confused context.

The solution is always the same: stop, undo the changes, and start a new session. When you reopen, rephrase the original problem differently or try a different model. Do not copy the old conversation into the new one.

9.4.4 Saving Your Progress to GitHub

You should regularly save working versions of your project to GitHub—the online platform where your code is stored (introduced in Pre-Work). Think of each save as a checkpoint in a video game. If something goes wrong later, you can always return to a checkpoint.

When to save to GitHub:

  • After you successfully complete a feature or fix.
  • Before you ask Cursor to make a large or risky change.
  • At the end of every working session.
  • Any time you think, "This is working well and I don't want to lose it."

How to do it: Ask Cursor in the agent chat. For example:

Please push the current version of my project to GitHub with the commit message "Homepage and login page working."

A commit message is a short note describing what state the project is in. Write something descriptive so you can identify which version to return to later. You do not need to learn Git commands—ask Cursor to handle the push for you.

9.4.5 Reverting to a Previous Version

If your project is in a bad state and you want to go back to a version that was working, you can retrieve a previous version from GitHub.

Steps:

  1. Ask Cursor to show your recent commits: 
    Show me the recent Git commit history for this project.
  2. Cursor will display a list of your previous saves (commits), each with the commit message you wrote and a timestamp.
  3. Identify the version you want to return to based on the commit message and date.
  4. Ask Cursor to revert to that version: 
    Please revert the project to the commit with the message "Homepage and login page working."

Reverting will undo all changes made after that save point. If you are unsure, ask Cursor to save the current state first:

Before reverting, please push the current version to GitHub with the commit message "Backup before revert — broken state."

9.5 Common Problems

This section covers specific issues you are likely to hit during the bootcamp, organized by topic. For each problem: the symptom, the likely cause, and how to fix it.

9.5.1 Setup and Installation

git is not recognized / command not found

Git is not installed on your computer. Follow the installation instructions in Pre-Work (Section 2.3). On Mac, run xcode-select --install in Terminal. On Windows, download the installer from git-scm.com. After installing, close and reopen Cursor so it picks up the new installation.

node is not recognized / command not found

Node.js is not installed. Follow the instructions in Our Tools (Exercise 7) or Dynamic Web Apps (Exercise 1). After installing, close and reopen Cursor (or open a new terminal) so it picks up the updated PATH.

What is PATH? PATH is a list of folders your computer checks when you type a command. When you install a program like Node.js, the installer adds its folder to PATH so the computer can find it. If you just installed something and the terminal says it can't find it, restarting Cursor usually fixes this because it reloads the PATH.

Cursor is not connected to GitHub

If pushing to GitHub fails with an authentication error, your Cursor may not be signed in to GitHub. Open the Source Control view (branch icon in the left sidebar), click Sign in with GitHub, and complete the sign-in in your browser. See Our Tools (Exercise 8).

9.5.2 Running Your App

Page is blank when opening an HTML file

If you're working on a static website (an HTML/CSS/JavaScript project like the one built in Build Your Own Website), double-click the index.html file in your project folder to open it in the browser. If the page is blank:

  • Make sure the file is saved in Cursor (Cmd+S / Ctrl+S). Unsaved changes don't appear.
  • Check that you are opening the correct file. The file should be named index.html and be at the top level of your project folder.
  • Paste the following into Cursor and attach the file with @: "My index.html file is blank when I open it in the browser. Can you check what's wrong?"

"Module not found" or "Cannot find module" when running npm run dev

This means a required package is missing. Run this command in the terminal (Ctrl+` to open the terminal in Cursor):

npm install

Then try npm run dev again. If it still fails, paste the full error message into Cursor and ask it to fix the issue.

npm run dev fails or the dev server won't start

The dev server is a local program that runs your Next.js app on your own computer so you can test it before deploying. When it's running, you visit http://localhost:3000 in your browser to see your app. If it won't start:

  • Read the error message in the terminal. Copy the entire error and paste it into Cursor.
  • Try stopping any running server first with Ctrl+C in the terminal, then run npm run dev again.
  • If the error mentions a port already in use, another process is using port 3000. Stop it by pressing Ctrl+C in all open terminals, or ask Cursor: "Port 3000 is already in use. How do I stop the process using it?"

Changes are not showing up in the browser

  • For static HTML files: Refresh the browser (Cmd+R / Ctrl+R). The browser caches old versions of the page. If a normal refresh doesn't work, try a hard refresh: Cmd+Shift+R (Mac) or Ctrl+Shift+R (Windows).
  • For Next.js apps: The dev server usually auto-refreshes. If changes still don't appear, stop the server (Ctrl+C) and restart it (npm run dev).
  • Make sure your files are saved (Cmd+S / Ctrl+S).

9.5.3 Deployment

GitHub Pages shows a 404 error

GitHub Pages needs a few minutes to deploy after you enable it or push changes. Wait 2–3 minutes and try again. If it still doesn't work:

  • Go to your repository on GitHub → Settings → Pages and confirm the source is set to your main branch and the / (root) folder.
  • Make sure your repository has an index.html file at the root level (not inside a subfolder).
  • Check the Actions tab in your repository for deployment errors.

Vercel build fails

When Vercel tries to deploy your Next.js app, it builds the project from your GitHub repository. If the build fails:

  1. Click View Build Logs on the Vercel dashboard to see the error.
  2. Copy the error message from the build logs.
  3. Paste it into Cursor and ask it to fix the issue.
  4. After Cursor fixes the code, push the changes to GitHub. Vercel will automatically try building again.

Tip: A common cause of Vercel build failures is code that works on your computer but has issues Vercel's stricter build process catches. Always test locally with npm run dev before pushing, and fix any errors you see in the terminal.

App works locally but not on Vercel

If your app works at localhost:3000 but not at your Vercel URL, the most common cause is a missing environment variable. An environment variable is a setting stored outside your code—like your InstantDB App ID—that your app needs to run. Your computer has these settings locally, but Vercel needs them configured separately.

  • Go to your Vercel dashboard → your project → Settings → Environment Variables.
  • Add any variables your app needs (e.g., NEXT_PUBLIC_INSTANT_APP_ID with your InstantDB App ID as the value).
  • Redeploy: go to the Deployments tab, click the three dots on the latest deployment, and select Redeploy.

9.5.4 Database and Authentication

Authentication not working (no verification email or code)

InstantDB's magic code authentication sends a 6-digit code to your email when you sign up or log in. If you're not receiving the code:

  • Check your spam/junk folder.
  • Verify your InstantDB App ID is correct in your code. Open the InstantDB dashboard, select your app, and compare the App ID shown there with the one in your code.
  • Ask Cursor: "Authentication is not sending a verification code. Can you check the InstantDB setup and make sure the App ID is correct?"

Data is not saving

If you can create items in your app but they disappear when you refresh the page or log out:

  • Check the InstantDB dashboard. Click your app, then go to the Explorer tab. If there is no data there, the app is not writing to the database correctly.
  • Ask Cursor: "Data isn't being saved to InstantDB. Can you check the database queries and transactions?"
  • Make sure you are logged in when creating data. Some apps require authentication before allowing writes.

Wrong App ID

If your app loads but shows no data, or if you see data from the poetry demo instead of your own project, you may be using the wrong InstantDB App ID. Each project needs its own App ID. Check the App ID in your code against the one in your InstantDB dashboard.
