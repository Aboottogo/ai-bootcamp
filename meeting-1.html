5.1 Ask Cursor to Plan and Build a How-To Tutorial Website

In Our Tools, you used Plan mode to build a poetry website. This time you'll use the same approach—Plan mode, review, Build—but for a different kind of project: a personalized how-to tutorial for your app idea. The tutorial teaches you how to build your app; it isn't the app itself.

You'll need my-app-idea.md from Pre-Work and a new project folder. The prompt below instructs Cursor to read two specification documents (tutorial-site-requirements.md and app-technical-requirements.md) before generating the tutorial.

5.1.1 Generate Your Tutorial Website

  1. Create a new folder on your computer (e.g. my-app-tutorial in Documents) and open it in Cursor (File → Open Folder).
  2. Have my-app-idea.md ready—either in the project folder or somewhere you can attach it (e.g. via @ in the Composer).
  3. Open the Agent (Composer) with Cmd+I (Mac) or Ctrl+I (Windows), then press Shift+Tab to switch to Plan mode.
  4. Copy the entire prompt below, paste it into the agent input, and attach your app-idea file (click the + button or type @ to add my-app-idea.md). Send the message.

    Tip: Copy the prompt exactly as it is given. Do not modify or change it. Make sure your my-app-idea.md is attached.

    I am a business student learning to build web apps with AI assistance. I have **never written code before**. I have attached my app idea file (`my-app-idea.md`) which describes the app I want to build. Please read it carefully before proceeding.

## Your Task
Create a **personalized, multi-page tutorial website** that will teach me how to build this specific app. The tutorial site itself should be a static HTML/CSS/JS website that I can host on GitHub Pages.

### 2. App Technical Requirements

**Read both documents completely before generating any files.**

## Key Requirements Summary

### Tutorial Site Must:

- Be split across **5 pages** (Introduction, Setup, Build, Deploy, Reference)
- Have a **persistent navigation bar** linking all pages
- Include **deep educational explanations** of concepts like frontend/backend, client-server model, etc.
- Have **code copy buttons** with "Copied!" feedback
- Have **collapsible FAQ sections** for troubleshooting
- Use **professional, minimal styling** with Tailwind CSS via CDN
- Be **fully personalized** to my specific app idea

### The App Must:

- Use **Next.js** with App Router
- Use **InstantDB** for database and authentication (Magic Code login)
- Use **Tailwind CSS** for styling
- Be deployable to **Vercel** free tier
- Include user accounts so users can save their own data

Extensions

Cursor supports extensions—additional features that can be installed directly into Cursor to improve its functionality. Extensions can help with formatting, debugging, live previews, and more. They are written by users like you and made available for others to use for free through the Extensions marketplace.

One common frustration: when you preview an HTML file by double-clicking it, you must manually refresh the browser every time you make a change. One solution is to install the Live Server extension by Ritwick Dey. It starts a local server and automatically reloads the page when you save a file.

To install and use Live Server:

  1. Click the Extensions icon in the left sidebar (or press Cmd+Shift+X on Mac / Ctrl+Shift+X on Windows).
  2. Search for Live Server, find the one by Ritwick Dey, and click Install.
  3. Right-click index.html in Cursor's file explorer and select Open with Live Server. The page will open in your browser and refresh automatically when you save changes.

5.2 Push the Project to a GitHub Repository

You pushed a project to GitHub in Our Tools (Exercise 10). Do the same for your tutorial project. Ask Cursor to do the push for you—you don't need to use the terminal or Source Control pane yourself. The goal is to practice letting Cursor handle Git tasks.

5.2.1 Push Your Tutorial to GitHub

  1. Create a new repository on GitHub:
    • Go to github.com/new
    • Name it (e.g. my-app-tutorial) and click Create repository
    • Don't initialize with a README, .gitignore, or license—your project already has files
  2. Copy the repository URL from the page GitHub shows you (e.g. https://github.com/your-username/my-app-tutorial)
  3. Open Cursor's Agent (Cmd+I or Ctrl+I) and ask it to push your project to that repository: 
    Commit all changes and push this project to my GitHub repository at https://github.com/your-username/my-app-tutorial

    Tip: Replace the URL in the prompt with your actual repository URL. Cursor will initialize Git if needed, stage your files, commit, and push—you don't need to run any commands yourself.

5.3 Publish Your Tutorial Website to GitHub Pages

You deployed in Our Tools (Exercise 11). Same steps for your tutorial site. GitHub Pages turns your repository into a live website—for free.

5.3.1 Publish Your Tutorial Website to GitHub Pages

  1. Make sure your project is pushed to GitHub (see Exercise above). Your repository should have an index.html at the root—GitHub Pages needs this as the entry point.
  2. On GitHub, go to your repository and click Settings (in the top menu bar).
  3. In the left sidebar, under Code and automation, click Pages.
  4. Under Build and deployment, under Source, select Deploy from a branch.
  5. Under Branch, choose your default branch (usually main) and select the / (root) folder.
  6. Click Save. GitHub will build and deploy your site.
  7. Wait a minute or two, then visit https://<your-username>.github.io/<repo-name>/ (replace with your GitHub username and repository name). Your site should be live!

    Tip: If you see a 404 at first, wait a few minutes—GitHub Pages can take 1–2 minutes to deploy. You can check the deployment status under the Actions tab in your repository.
